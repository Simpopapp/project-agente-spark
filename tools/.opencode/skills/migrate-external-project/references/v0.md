# v0

This playbook narrows the parent skill's acquisition, inspection, and data handoff for v0. Use the parent skill for the migration lifecycle, provider decisions, and verification.

## Acquire

When no source material is attached, give these steps:

1. Open the project in v0.
2. Select the **⋯** menu in the top-right toolbar.
3. Select **Download ZIP**.
4. Attach the ZIP in this chat.

End by asking the user to attach the ZIP. Accept an existing GitHub repository URL instead, but lead with the ZIP path. Skip these instructions when source material is already available.

## Inspect

Inspect `package.json` before naming the framework or version. Check App Router pages, server actions, route handlers, auth and authorization, database schema and client, storage, AI SDKs, payments, analytics, and environment-variable names.

Treat `V0_*` and `VERCEL_*` variables as source-platform runtime metadata unless application call sites prove they configure a production capability. Do not request them as user-owned secrets.

Treat the code ZIP as code and schema only unless it contains explicit CSV or JSON record exports. A bundled Drizzle, Prisma, or SQL schema does not prove that production records were included. Identify the connected database provider from code or configuration; when records are absent, build the app and schema, mark records pending, and give that provider's export steps after the preview.

Keep auth tables separate from application data. Never ask the user to upload password hashes, sessions, verification tokens, access tokens, or refresh tokens. Apply the parent skill's existing-user decision before replacing Better Auth or another auth provider.

## Handoff

When records remain pending, lead with **Next: add your existing data**. Name the detected database provider, ask for application tables as CSV or JSON, exclude auth credential tables and secret values, then end with **Or reply “Skip for now.”**
